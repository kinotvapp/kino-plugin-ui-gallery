# Kino UI gallery

[Español](README.es.md)

A plugin whose only job is to show what a Kino plugin screen can look like. Every component of the screen kit has its own
section with a live, interactive example, on the phone and on the TV: layout, text and images, buttons and forms, lists,
dialogs and sheets, tabs and navigation, animations and more.

It is an example for plugin authors, **and a worked example of how to build a plugin from many files**: you read and edit the
small, structured source in [`src/`](src), and one command bundles it into the single [`plugin.js`](plugin.js) that Kino
loads. It does not play anything and it is **not listed in Kino's plugin search or recommendations**
(`"discoverable": false`): you install it by its address.

## How it is built

Kino loads exactly one file (the manifest's `entry`) and has no module resolver, so the file it reads cannot `import` a second
one. That does not mean a plugin has to be written in one file: write it as modules, then bundle it.

```
src/ ──  npm run build  ──▶  plugin.js  ──  npm run sign  ──▶  kino-plugin.json (signature)
(how it is written)          (what Kino reads)
```

The result, `plugin.js`, is generated: do not edit it by hand. Edit `src/`, run the build, and commit both.

### The files

```
kino-plugin-ui-gallery/
├── src/                        the source, written as modules
│   ├── plugin.js               the entry point: exports what Kino calls, screen() and screenEvent()
│   ├── constants.js            the list of tabs, the icon names, and the public pictures and addresses the examples use
│   ├── helpers.js              small builders shared by every tab: t() (Spanish + English), caption(), para(), section()
│   ├── demo-items.js           three sample items for the examples of Kino's own cards
│   ├── state.js                the screen's starting state, and reading back whatever Kino kept
│   ├── view.js                 draws the screen: the tab bar, the declared pop-ups, the Scaffold route; calls the tabs
│   ├── events.js               answers each event (a tap, a change, a timer tick) with a new state
│   └── tabs/                   one file per tab: each section is one component with a live example
│       ├── layout.js           Column, Row, Stack and positioned children, Spacer, Divider, Scroll, GridView, Card,
│       │                       ExpansionTile, TabBar, ListView, ListTile, PageView, a Scaffold screen
│       ├── content.js          Text and colour roles, Image, Icon (every icon), Badge, CircleAvatar, banner, Skeleton,
│       │                       QrImage, DataTable, progress, empty and error states, Kino's own cards
│       ├── actions.js          buttons, slow presses, wait-to-send countdown, floating button, tooltips, chips, toasts
│       ├── forms.js            Form with validation, your own verdict, inputs, the plugin's settings
│       ├── overlays.js         dialogs, sheets, menus, declared pop-ups
│       ├── navigation.js       open a link, title by ids, this screen at a route, a route of your own, close
│       └── data.js             state, events, timer, per-size values, boxes and texts, animations, style tokens
├── plugin.js                   GENERATED by `npm run build`: the single file Kino reads (and signs)
├── kino-plugin.json            the manifest: id, apiVersion 14, the screen entry, the signature
├── package.json                the commands below, and esbuild (the only dev dependency)
├── scripts/sign.mjs            signs plugin.js with the maintainer's key (not needed to read or build)
├── sdk/                        Kino's plugin kit: validator, runner and test helpers
├── contract.json, kino.d.ts    the plugin contract the kit checks against, and its types
├── test/gallery.test.mjs       the tests
└── LICENSE                     MIT
```

### The commands

```bash
npm install          # once: installs esbuild
npm run build        # src/ -> plugin.js (the file Kino reads)
npm test             # the tests, including "plugin.js is exactly what building src/ produces"
npm run validate     # build + Kino's own validator: "Kino would accept this plugin"
npm run sign         # build + sign, for the maintainer (needs the author key; never committed)
```

The build is a single esbuild command, in `package.json`:

```bash
esbuild src/plugin.js --bundle --format=esm --target=es2020 --outfile=plugin.js
```

`plugin.js` keeps a `// src/…` comment above each module, so even the bundle tells you where each part came from. The guide
explains the idea in ["Splitting your code across files"](https://kinotvapp.github.io/kino-plugins/).

## Requirements

- Kino **0.9.74 or later** (the plugin uses `apiVersion` 14, the screen kit). An older Kino says it needs a newer version.

## Install

1. In Kino open **Plugins ▸ Agregar plugin**.
2. Type `kinotvapp/kino-plugin-ui-gallery` and confirm.
3. Open **UI gallery** from the menu, or from the plugin's page in Plugins ▸ Installed ▸ Manage.

## Learn more

- The plugin guide and the screen reference (every component, property and event): <https://kinotvapp.github.io/kino-plugins/>
- Try your own screens with the kit: `node sdk/validate.mjs .` and `node sdk/run.mjs . screen`.
